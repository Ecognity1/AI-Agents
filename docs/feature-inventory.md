# Folio Feature Inventory

Derived from the current implementation on 2026-08-04. The application is a Vite/vanilla-JavaScript storefront with a local HTTP API, JSON-file persistence, Node tests, and Playwright browser tests.

| ID | Feature | Module | Description | Page/component/API | Roles | Preconditions | Main behavior | Dependencies | Criticality | Testability |
|---|---|---|---|---|---|---|---|---|---|---|
| FEAT-001 | Catalog browsing | Catalog/storefront | Presents purchasable books with price, availability and result count | Catalog grid; `GET /api/v1/books` | Shopper | Local API available | Loads and renders available books; exposes loading, empty and error states | Catalog data, API | High | UI and API observable |
| FEAT-002 | Search, filter and sort | Storefront/store | Refines books by query, category, format, price and availability and orders results | Search/filter controls; `filterBooks` | Shopper | Catalog loaded | Composes refinements, shows count, clears search/refinements | FEAT-001 | High | Unit and UI observable |
| FEAT-003 | Book details | Storefront | Shows complete selected-book information and purchase availability | Product details dialog | Shopper | Book rendered | Opens semantic dialog with metadata, stock and add action | FEAT-001 | Medium | UI observable |
| FEAT-004 | Shopping bag | Store/cart | Adds, removes and clamps item quantities; calculates and persists totals | Bag dialog; localStorage; store functions | Shopper | Available book | Maintains cart across reload and prevents quantity beyond stock | Catalog, browser storage | Critical | Unit and UI observable |
| FEAT-005 | Checkout review and validation | Storefront/commerce | Collects minimum order data and displays authoritative totals | Checkout dialog; quote/order API | Shopper | Non-empty valid cart | Validates fields, reviews items/shipping/tax/total and preserves recoverable input | FEAT-004, API | Critical | Unit, API integration, UI |
| FEAT-006 | Payment outcome and retry | Commerce/local adapter | Simulates development success or decline with safe retry/idempotency | Payment radios; `POST /api/v1/orders` | Shopper | Valid checkout | Decline produces guidance without order; switching to success permits one order | Local payment adapter, idempotency key | Critical | Unit/integration/E2E |
| FEAT-007 | Durable order confirmation | Commerce/repository | Persists an immutable order snapshot and shows a unique reference | Confirmation dialog; JSON repository | Shopper | Successful payment | Creates `FOL-*` order, adjusts stock, clears cart and displays confirmation | Repository, FEAT-006 | Critical | Integration and E2E |
| FEAT-008 | Catalog operations | Admin/API | Updates stock and sale availability with an audit event | Staff dialog; `PATCH /api/v1/admin/books/{id}` | CatalogAdmin | Local admin token/role | Validates and persists stock/availability; storefront refreshes | Authorization, repository | High | API integration and E2E |
| FEAT-009 | Order operations | Admin/API | Lists placed orders and displays selected order details | Staff dialog; admin order endpoints | OrderOperator | Local admin token/role; existing order | Lists references/customers and reveals authorized order detail | Authorization, repository | High | API integration and E2E |
| FEAT-010 | Local role authorization | Commerce/API | Defaults admin actions to deny and separates catalog/order roles | Admin API headers; `requireRole` | CatalogAdmin, OrderOperator | Explicit development token and role | Allows only matching role; returns safe forbidden errors otherwise | Local identity adapter | Critical | Unit/API testable |
| FEAT-011 | Recoverable UI states | Storefront/API client | Communicates loading, validation, decline, API failure and retry states without discarding input | Alerts, empty/loading panels, retry controls | Shopper, staff | Triggered state | Shows actionable status and refresh/retry paths | API/network | High | UI and controlled failure testing |
| FEAT-012 | Accessibility and responsive use | Storefront/styles | Supports semantic labels, keyboard closing/focus restoration and desktop/tablet/mobile layouts | Skip link, dialogs, responsive CSS | All users | Browser | Keyboard flow remains usable and critical controls remain visible at configured viewports | Browser/CSS | High | Playwright plus manual review |
